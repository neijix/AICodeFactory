# Tests

Run these before committing a change to `sync-ai-templates.sh`, `sync-ai-templates.ps1`,
`templates-manifest.txt`, or the SessionStart hook in `templates/.claude/settings.json.template`.

```bash
tests/run-tests.sh                                  # bash engine, against /bin/bash (what the hook uses)
tests/run-tests.sh --bash "$(command -v bash)"      # and again against a newer bash
pwsh -NoProfile -File tests/run-tests.ps1           # PowerShell engine (the twin)
uv run python -m unittest tests.test_factory_env    # factory config, stamp, keep, 3-way JSON merge
/usr/bin/python3 -m unittest tests.test_factory_env # same on macOS's 3.9: the hook's engine runs on it
uv run python -m unittest tests.test_projects_page   # aicf projects: status, transcript skill use, escaping
```

`tests/test_factory_env.py` does not need the sandbox. The engine suites stay valid when no
`factory.json` and no `environment.json` exist: the sync then writes nothing new.

Each run builds a throwaway sandbox (`mktemp -d`) with its own `HOME` and its own
`GIT_CONFIG_GLOBAL`, so nothing touches your real projects, your global skill folders, or
your git identity. Add `--keep` / `-Keep` to inspect the sandbox afterwards.

The PowerShell twin also overrides `USERPROFILE`, not just `HOME`: PowerShell's automatic
`$HOME` — which the engine uses to find the global skill folders — is derived from `USERPROFILE`
on Windows and ignores `$env:HOME`. Without that override the suite reaches into the real profile
and can rewrite the skills installed there.

**On Windows both suites skip the symlink cases** (4, 7, and the link-mode halves of 9/9b/15):
creating a symlink needs Developer Mode or an elevated shell, and Git Bash otherwise fakes
`ln -s` by copying. Each suite probes the capability once and says which cases it skipped —
skips are printed, never silent. Windows installs skills as copies anyway, so nothing that
actually runs there goes untested. The bash suite also picks whichever of `python3`/`python`/`py`
really works (on Windows `python3` is often the Microsoft Store stub) and feeds it the hook JSON
on **stdin**, since a native Windows python cannot open a Git Bash `/f/...` path; with no system
python at all, both suites use `uv python find`. `chmod 000` does nothing under Git Bash, so the
bash suite also skips the unreadable-input halves of cases 15 and 19 there (the PowerShell twin
skips its own on Windows).

## ui-doctor

`tests/test-ui-doctor.py` (plain `python3`, also a CI step) runs the `ui-doctor` skill's script
on `tests/ui-doctor/bad/` — every static rule must fire at its `file:line` — and on
`tests/ui-doctor/good/`, where every row must be OK (JSX braces, spreads, `htmlFor`, wrapping
labels: no false positive). With `uv` and a Chrome / Edge it also loads both fixtures over
`file://` in headless Chrome: the bad page must give each live finding, the good one must pass
in light and emulated dark mode. Without them it prints one `SKIP` line. Silent on success.
